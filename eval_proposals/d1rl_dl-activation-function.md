**Mocking:** DL Activation Function Design

Let me start from the exact failure mode I can observe rather than from a textbook function. I'm not here to invent a new function — I'm here to design a function that *fits* the ResNet/VGG/CIFAR context, and the only honest data I have is that ReLU's zero-gradient negative domain is *harmful* there, while ReLU6's linear negative domain is *too soft* on the training side.

So the first move is to stop asking "which activation is best" and ask "which activation behavior is *necessary* here." The two competing intuitions are:

1. The negative domain must *not* kill gradients — so it should not be zero (dead ReLU), and it should not be flat (ReLU6). A bounded negative domain (softplus) or a learnable negative domain (negative slope) is the only candidate that can satisfy both "no dying" and "not too soft."

2. The *positive* domain must be *smooth* enough to carry gradient information through residual blocks, because ReLU's sharp kink in the positive domain is exactly the kind of discontinuity that destroys the residual signal. This forces the activation to be a *smooth* monotonic function (a CDF-like weighting), not a piecewise linear one.

Now the creative leap — these two requirements (no dying + smooth) are not compatible with a single *fixed* function. So I don't pick one existing function and tune it. I *compose* two behaviors into one family of functions. That's the transfer from signal processing: a smooth function with a learnable slope in the negative domain is a *family* of smooth functions, not a single one.

Here's the non-trivial crux I want to force myself to see clearly: the *same* function family cannot be both monotonically increasing and non-monotonic at the same time. If I fix a single weight, the function is monotonic (like GELU); if I make it non-monotonic (like SiLU), the slope is *fixed* and I lose the learnable negative-domain flexibility. So the two desirable properties — smoothness and learnable negative-domain — are *orthogonal* and I cannot get both with one fixed parameter. The only way to get both is to *add* a second learnable parameter: a learnable slope for the negative domain, *and* a smooth monotonic positive domain.

Let me be precise about what each parameter does and how they interact, because that's where the design lives and where the whole idea collapses if I'm not careful:

- **Learnable slope (β)**: This is the negative-domain slope, so it's a *second* learnable parameter. It must be *negative* to be in the negative domain. If β were positive it would gate the negative domain back into the positive — that would be a non-monotonicity I don't want. So β is strictly negative, and it's *learnable* so the network can adapt it to the architecture/data rather than having to choose it by hand. This is the only place a learnable parameter is justified — the negative-domain behavior is the only part that genuinely needs to be learned; the positive domain is already smooth enough by construction.

- **Smooth monotonic domain**: The positive part is a *smooth* function that is strictly increasing everywhere. GELU's Gaussian CDF is one example — it's smooth and monotonic. But I can also write it as a *generalized logistic CDF* with learnable parameters, which is strictly monotonic and differentiable everywhere (including near zero), and it has an extra knob (the logistic shape) that I can expose to the network. The logistic CDF is a better choice than the Gaussian CDF here because it's more flexible and can approximate any smooth monotonic function with the right shape — that's the *flexibility* I want the network to exploit.

Why is this a win and not just a prettier ReLU? Because a fixed function like ReLU cannot cover the negative-domain spectrum across different architectures (ResNet vs VGG), and a *learnable* negative-domain slope β makes the activation itself an *architecture/data-dependent* object rather than a universal constant. The network learns the *correct* negative-domain behavior for its own residual structure — a property that a single fixed function cannot have.

How do I keep myself honest? I won't claim victory from a single number. I'll run this on ResNet-20 (CIFAR-10) and VGG-16-BN (CIFAR-100), and I'll compare *two variants*: the learnable-slope version and a fixed-slope version (fixed negative slope, smooth positive domain) — because the learnable slope is the whole contribution, not the smooth domain. If the learnable-slope variant does *not* beat the fixed-slope one, then the learnability isn't earning its place and I drop it. And I'll keep the *same* network architecture, optimizer, and data augmentation throughout — otherwise any accuracy lift is indistinguishable from a network effect, not a function effect. Decision rule: if the learnable-slope version doesn't clearly outperform the fixed-slope version on both ResNet-20 and VGG-16-BN, the learnability is an illusion and I revert to a simpler form.

**Core idea:** Build a smooth activation family with two learnable parameters — a learnable negative-domain slope (β, strictly negative) and a smooth monotonic positive-domain function (e.g. a generalized logistic CDF) — so the network can adapt the negative-domain behavior to its own residual structure.
**Non-trivial crux:** The learnable slope β must be strictly negative (to keep monotonicity), and the smooth positive domain must be strictly increasing everywhere — these are two *orthogonal* properties that can only coexist by adding a second learnable parameter, not by tuning a single one.
