**Mocking:** myself, as a researcher, not a code reviewer

Let me start from the thing that actually bothers me, not from any theory. I run ResNet-20 on CIFAR-10 with ReLU and the test accuracy hovers around 89-90%. That's not a bad number, but I notice the tail is a bit flat — it doesn't look like it's hitting a genuine ceiling; it looks like I've just reached the limit of what ReLU can do here. The number itself isn't the objection — the objection is that I'm staring at a network that already has residual connections, batch normalization, and a fairly deep architecture, and yet the activation I'm using is essentially just a piecewise linear function that has zero gradient for negative inputs. That zero gradient is exactly the thing that could be holding me back. So my hypothesis is: a better activation should make that plateau sharper, and the plateau is where most of the test accuracy lives. I'm betting that a smoother, non-saturating function could push the tail higher.

Now I have to be precise about what I'm allowed to change. I can't add new network components — only the activation inside the `CustomActivation` class. That means the whole improvement has to fit into that one forward pass: a learnable, stateless, channel-wise transformation.

Here's where I want to be careful not to fall into a trap. A lot of people try to design a new activation by just inventing a formula and tuning its single parameter. That's the classic "add a knob and tune it" mistake. If I pick a formula and then only tune one parameter, I don't know which part of the formula is actually doing the work. So the honest move is: don't pick a formula yet. Instead, fix a *structure* that's plausibly what I want — a smooth, self-gated, non-monotonic function with a learnable bias in the negative domain — and then *let the data tell me what the parameters should be*. Let the loss itself decide the shape.

What would a good candidate shape look like? Gated functions (x * σ(x), x * tanh(something)) have this nice property: they are always positive, they're non-monotonic, and they never die. Swish and SiLU are exactly that: self-gated, smooth, and non-saturating. If I keep the *gating* but change the *gate* — replace the sigmoid with a different smooth nonlinearity — I might get something that still doesn't saturate but is more expressive. And I want a negative-domain bias that's *learnable*, not fixed at 0 — because a fixed zero would just be the same as ReLU.

So the mechanism I'm leaning toward is: a self-gated form (x * σ(gate(x)) where gate(x) = tanh(softplus(x)) — that's Mish's gate) with a learnable negative-domain bias. I won't fix the parameter values; I'll let the loss find them. That's the non-trivial crux: the value of the parameter is not a knob to tune but a *part of the training objective* — the same way a learnable bias in a linear layer is part of the objective, not a hyperparameter. If I had fixed the bias at zero, I'd have been cheating, and I wouldn't know if the gain was real or just the fixed zero. By making it learnable, the number I get is the real number the network found.

One more thing that might matter, but I have to keep it honest: the function should be non-saturating everywhere, because a saturating activation is exactly the kind of thing that could hurt gradient flow. That's the whole point — a function that keeps flowing through the negative region without dying is the whole game.

**Core idea:** Design a self-gated activation as a learnable, non-saturating function (x * σ(gate(x)) with gate(x) = tanh(softplus(x)) and a learnable negative-domain bias), letting the loss itself determine the parameters instead of tuning them.

**Non-trivial crux:** The parameter values are not hyperparameters to tune but a *part of the training objective* — the same as a learnable bias; fixing them at zero (the ReLU baseline) would be cheating, and you only get to know the gain is real if you let the loss find the bias.
