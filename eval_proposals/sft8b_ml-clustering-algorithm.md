**Mocking:** myself as a researcher

Let me start from the thing I actually care about, not from an existing method. When I look at the evaluation metrics — ARI, NMI, Silhouette — they are all measuring the *quality* of cluster assignments relative to a ground truth. So before I touch any algorithm, I want to ask: what is the *true* signal I'm trying to recover? A cluster is a group of points whose mutual distances are small, and whose distances to other clusters are large. That's the definition. Every clustering algorithm is just a way to compute that signal from noisy data.

Now the observation that cuts against the standard story: the default distance metric (Euclidean) is not the *correct* distance for real datasets. In a moons dataset, two points on opposite sides of a gap are very far in Euclidean space even though they are clearly the same cluster. In a digits dataset, some features are categorical and others are continuous, and the usual distance treats them all as real numbers. So my first move is not to invent a new algorithm — it's to ask: what distance metric is actually appropriate for the data?

That reframing gives me a concrete, falsifiable idea: construct a distance metric that is *robust to scale differences across features* and *handles mixed-type features*. The standard way to do this is to normalize each feature by its range (min-max) — which is exactly what StandardScaler does. Min-max is not an approximation; it's the *definition* of a distance that is invariant to feature scaling. For a single feature, range normalization makes distances symmetric and feature-invariant; for multiple features, it's the natural way to combine them into a single metric that treats each dimension fairly.

Why is this a research question rather than a cookbook fix? Because normalization changes the *geometry* of the data. If I normalize features that are naturally on different scales, I am essentially *distorting the space* to make a uniform metric. That distortion is exactly what I must understand, not just apply. The honest move is to treat this as a hypothesis: the distance metric is the signal; the algorithm is the interpreter. So I want to test it with *all* the datasets — not just blobs. The decision rule is clear: if min-max normalization does not clearly help (e.g. if ARI/NMI do not improve over unnormalized Euclidean on varied-density and digits), I must drop it and explain why, not force it. This is a falsifiable claim, not an opinion.

Now, how to make this concrete in the code. The interface already gives me a `custom_distance` function — that's the hook. I can implement it as a min-max-normalized Euclidean distance: for each feature, scale the data by its range, then compute the usual Euclidean distance on those scaled values. (I'll have to handle zero-variance features carefully — those features don't contribute to the metric, so they can be ignored.) Crucially, I must normalize the *training data only*, not the test data, so the fit/predict split is correct.

Why does this cut against the consensus? The field's default is to assume Euclidean distance is fine and that the algorithm is what needs improvement. I'm arguing the opposite: the wrong metric is the primary failure mode, and the right metric can be cheap to compute (just scaling and a standard formula).

**Core idea:** Construct a distance metric (min-max-normalized Euclidean) that is scale-invariant and handles mixed-type features, then use it as the foundation for any clustering algorithm — treating the metric as the signal to be correctly measured, rather than assuming the algorithm is the bottleneck.

**Non-trivial crux:** Min-max normalization is a *geometric transformation*, not an approximation — it changes the space so a uniform metric is feature-invariant; this is exactly what you must verify (and potentially reject) across all dataset types, not assume in advance.
