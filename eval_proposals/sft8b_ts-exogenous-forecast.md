**Mocking:** myself, as a world-class researcher, not as a code-writer. I'm looking for a genuinely better model, not a fancier one. So I refuse to start with the architecture.

Let me reason directly from the data and the objective. The target is a scalar time series. Three datasets, all MS features. Every reference model takes the whole feature set and predicts only the last dimension. Why? Because the task is scalar regression, not multi-step or multi-target. That's the invariant I can lean on. So the design question is: what does the target really depend on? The target variable is a single time series, so its dependencies should be *local* in time and *local* in features — not spread across the whole feature matrix.

Now the deductive leap: if the target is scalar, its dependencies are likely confined to a small window of past values and a small window of related features. The references treat all 21 or 321 features as a global entity; that's wasteful and may overfit. So the model should decompose the feature matrix: partition the features into a *local* subset (e.g. a small set of related features) and a *global* subset (a few scalar time series). Then the model can explicitly *separate* modeling of these two kinds of dependencies.

Why does this cut against the consensus? Because the prevailing instinct — 'more input is always better' — would suggest including everything. But scalar regression has a strong argument in favor of sparsity: too many input dimensions dilute the signal and overfit. The decision rule is: if the target is scalar and a small subset of features correlates strongly with it, keep only those and treat the rest as global. If no such subset exists, keep all as local — but that's a hypothesis to check, not an assumption to assert.

How do I keep myself honest? I don't get to assert which features are local or global. I build the model so that the user can swap the local/global split, and I compare a couple of reasonable splits (say, a few strongly-correlated features vs. all) on the same validation set. Decision rule: choose the split that yields the lowest MSE and MAE on the validation set, and report it — if no clean split is found, treat the whole feature set as global. The code must stay modular so this choice is an option, not a fixed rule.

**Core idea:** Since the target is scalar, decompose the feature matrix into a small *local* subset (strongly-correlated features) and a few *global* scalar time series, then explicitly model these two types of dependencies — keeping the split as a modular, testable choice.

**Non-trivial crux:** The split must be chosen by validation set performance, not asserted in advance; if no clean subset is found, treat the whole feature set as global — but the decision rule is only valid if the feature decomposition is truly separating local and global dependencies, not if the scalar target is truly scalar.
