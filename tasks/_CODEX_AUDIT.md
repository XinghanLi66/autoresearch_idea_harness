# Codex Audit: Four Trimmed MLS-Bench Tasks

Source: gpt-5.5 xhigh via codex-plugin-cc, task-molfktad-t0l322, 2026-04-30.

## llm-qat-algorithm
The four edits are mostly faithful controls: `no_qat` is per-group RTN max-abs QDQ (`tasks/llm-qat-algorithm/edits/no_qat.edit.py:51`), `ste` uses STE fake quantization (`tasks/llm-qat-algorithm/edits/ste.edit.py:35`; https://arxiv.org/abs/1308.3432), `lsq` implements learned step-size gradients and initialization (`tasks/llm-qat-algorithm/edits/lsq.edit.py:37`, `:99`; LSQ Sec. 3.2/3.4, https://arxiv.org/abs/1902.08153), and `finetune_then_ptq` is float finetune then RTN (`tasks/llm-qat-algorithm/edits/finetune_then_ptq.edit.py:51`, `:60`). The task text is stale: it says 1500 steps and seqlen 2048 (`tasks/llm-qat-algorithm/task_description.md:31`, `:75`), but code uses 500 steps and seqlen 1024 (`tasks/llm-qat-algorithm/edits/custom_template.py:35`; `tasks/llm-qat-algorithm/scripts/qat_eval_int4_g128.sh:13`). The leaderboard has stale GPT-2 columns, duplicate current `no_qat`, and no mean row (`tasks/llm-qat-algorithm/leaderboard.csv:1`, `:6`). INT2 RTN collapse is plausible versus BiLLM RTN W2g128 Table 3 (https://openreview.net/forum?id=5xEgrl_5FAJ), while LSQ INT2 is not directly comparable to OmniQuant/EfficientQAT LLaMA-2 W2/W3 tables because this task uses Pythia and a different recipe (`tasks/llm-qat-algorithm/task_description.md:153`; https://arxiv.org/abs/2308.13137 Table 1; https://arxiv.org/abs/2407.11062 Table 2). Missing cheap baselines: OmniQuant-style PTQ, about 100-150 LoC, and LR-QAT-style low-rank QAT, about 80-120 LoC (https://arxiv.org/abs/2407.11062 Table 2).

## mlsys-sparse-attention-inference
`streaming_llm` implements sink plus sliding window (`tasks/mlsys-sparse-attention-inference/edits/streaming_llm.edit.py:53`; StreamingLLM Sec. 3.2, https://arxiv.org/abs/2309.17453), and `bigbird` implements global/window/random blocks (`tasks/mlsys-sparse-attention-inference/edits/bigbird.edit.py:1`; BigBird Sec. 2, https://arxiv.org/abs/2007.14062). `block_topk` is only NSA-style selected block top-k, not full NSA compressed+selected+sliding attention (`tasks/mlsys-sparse-attention-inference/edits/block_topk.edit.py:52`; NSA Fig. 1, https://arxiv.org/abs/2502.11089). The main bug is that `dense` runs true dense SDPA but reports `last_density = density_budget` (`tasks/mlsys-sparse-attention-inference/edits/dense.edit.py:34`, `:42`), while scoring rewards lower density/time (`tasks/mlsys-sparse-attention-inference/score_spec.py:24`). Parser keys are structurally fine because labels emit distinct metric names (`tasks/mlsys-sparse-attention-inference/parser.py:40`), but the leaderboard has stale `pg19_*` columns, split rows, and duplicate empty rows (`tasks/mlsys-sparse-attention-inference/leaderboard.csv:1`, `:4`). LongBench numbers are directionally plausible only as task-local values: XAttention Table 2 gives comparable sparse/full Qasper and MultiFieldQA references, but not this exact Qwen setup (`tasks/mlsys-sparse-attention-inference/task_description.md:26`; https://arxiv.org/abs/2503.16428). Missing cheap baselines: MInference/FlexPrefill-style dynamic sparse selection, about 80-120 LoC, and full three-branch NSA, about 100-150 LoC (https://arxiv.org/abs/2407.02490; https://arxiv.org/abs/2502.11089).

## mlsys-kv-cache-eviction
`streaming_llm` keeps sink plus recent KV tokens (`tasks/mlsys-kv-cache-eviction/edits/streaming_llm.edit.py:34`; https://arxiv.org/abs/2309.17453 Sec. 3.2), and `snapkv` follows observation-window scoring plus max-pooling (`tasks/mlsys-kv-cache-eviction/edits/snapkv.edit.py:40`, `:78`; SnapKV Sec. 3.1/Table 1, https://arxiv.org/abs/2404.14469). `h2o` is a one-shot prefill adaptation using recent-window attention mass and an 80/20 heavy/recent split (`tasks/mlsys-kv-cache-eviction/edits/h2o.edit.py:53`, `:76`), while H2O defines dynamic heavy-hitter retention during generation (H2O Sec. 4, https://arxiv.org/abs/2306.14048). `dense` reports budget density while returning the full cache (`tasks/mlsys-kv-cache-eviction/edits/dense.edit.py:30`; `tasks/mlsys-kv-cache-eviction/score_spec.py:24`). The task claims physical KV compression (`tasks/mlsys-kv-cache-eviction/task_description.md:4`), but the harness still updates HF `DynamicCache` with full K/V while separately using compressed attention state (`tasks/mlsys-kv-cache-eviction/edits/mid_edit.py:176`, `:114`). Leaderboard magnitudes are plausible versus SnapKV Table 1 for Mistral-7B-Instruct-v0.2 LongBench, but exact values should not be treated as paper reproduction because the harness caps context/cases (`tasks/mlsys-kv-cache-eviction/scripts/qasper.sh:10`; https://arxiv.org/abs/2404.14469 Table 1). Missing cheap baselines: PyramidKV, about 50-80 LoC, and Ada-KV, about 80-120 LoC (https://arxiv.org/abs/2406.02069 Table 1; https://arxiv.org/abs/2407.11550).

## llm-pretrain-sparse-attention
`dense` is a valid dense SDPA oracle (`tasks/llm-pretrain-sparse-attention/edits/dense.edit.py:26`), but `nsa_full` is not full NSA because `TOP_K=1` keeps only the diagonal selected block (`tasks/llm-pretrain-sparse-attention/edits/nsa_full.edit.py:40`, `:129`; NSA Fig. 1, https://arxiv.org/abs/2502.11089). `moba` and `reformer` implement recognizable block routing and LSH chunk attention (`tasks/llm-pretrain-sparse-attention/edits/moba.edit.py:71`; `tasks/llm-pretrain-sparse-attention/edits/reformer.edit.py:63`; Reformer Sec. 2.1, https://arxiv.org/abs/2001.04451), but both assert sequence divisibility and likely explain missing hidden lm-eval metrics (`tasks/llm-pretrain-sparse-attention/edits/moba.edit.py:63`; `tasks/llm-pretrain-sparse-attention/edits/reformer.edit.py:100`; `tasks/llm-pretrain-sparse-attention/leaderboard.csv:4`). The setup is GPT-2-medium scale on ClimbMix (`tasks/llm-pretrain-sparse-attention/scripts/gpt_345m.sh:4`; `vendor/pkg_configs/nanoGPT/config.json:36`), and dense val loss is not suspicious relative to nanoGPT OpenWebText GPT-2 references because dataset/token budget differ (`tasks/llm-pretrain-sparse-attention/task_description.md:45`; https://github.com/karpathy/nanoGPT). The leaderboard is incomplete for sparse baselines and repeats empty `nsa_full` rows (`tasks/llm-pretrain-sparse-attention/leaderboard.csv:3`, `:11`). Missing cheap baselines: Longformer sliding+global, about 40-60 LoC, and BigBird pretraining attention, about 60-90 LoC (https://arxiv.org/abs/2004.05150; https://arxiv.org/abs/2007.14062 Sec. 2).
